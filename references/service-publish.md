# Service and publishing

Publishing and promotion, REST calls and sign-in, published-model drift, column type changes, reading a model at volume. Rows moved verbatim from the v1 SKILL.md quick reference in v2.0.0; `§` references point to [reference.md](../reference.md). Where a row disagrees with the core, the row wins.

The core publishes models with `createItemWithDefinition` or `updateDefinition` and reports with `pack` plus the items API. Overlay: update in place by item id, never delete a published model to redeploy it (overrides in SKILL.md). Any XMLA write to a published model, a TOM deploy in a row below included, ends its PBIX download: tell the owner before taking that route.

| Situation | Rule |
|---|---|
| Promoting a generated project to another workspace | Generate it again into its own root from the target environment's ids (fresh `logicalId`s, no `.pbi` folders), prove it against a source build from the same generators (only the environment values may differ), then a leak-sweep environment gate. A first Desktop publish lands at the workspace root (move by the items API), and a TMSL refresh against a new database waits silently behind Desktop's credential dialog. reference.md §2026-11-10 round 20. |
| Publish fails: *Part URI is not valid per rules defined in the Open Packaging Conventions specification* | A file under the `.Report` folder has a name that is not a valid raw OPC part name - usually a SPACE in a `StaticResources` file (a hand-named theme). Desktop packs file paths unescaped; it names its own resources `Name_With_Underscores<digits>.json`. Rename the file, fix the three references in `report.json`, delete the old file (everything in the folder is packed), reopen Desktop. Reproduce offline with `System.IO.Packaging.Package.CreatePart` on raw paths. reference.md §2026-09-21 round 3. |
| A REST call from a PowerShell harness returns 403 with an EMPTY body, every retry | Check your own request first: a helper named `H` is the built-in alias of `Get-History` (aliases beat functions, like `R`, `Diff`), so `-Headers (H)` sent no Authorization. Never use one- or two-letter helper names; `Get-Alias <name>`. reference.md §2026-10-20 round 2. |
| Column TYPE change on a published model | Fabric `updateDefinition` fails with `Alm_InvalidRequest_PurgeRequired` even after `clearValues`. Deploy over XMLA: TOM `TmdlSerializer` → `JsonScripter.ScriptCreateOrReplace` → `Server.Execute`, from a VISIBLE `powershell.exe` window (AMO refuses interactive auth from a non-interactive host), launched via a BOM-encoded launcher on an ASCII path. `Server.Refresh()` still shows old metadata - verify via `getDefinition`. Facts come back empty → policy load per table, dims first. reference.md §2026-09-09. |
| Device-code sign-in with no interactive console (agent-driven) | Launch the script DETACHED (`Start-Process` / a backgrounded `pwsh -NoProfile -File`), write the `devicecode` endpoint's `message` verbatim to a prompt file for the operator to act on, and let the script poll the token endpoint itself to a deadline. Token in a process variable ONLY (null the rest of the payload the moment you read `access_token`), prompt file deleted in a `finally` so a stale code is never shown, `authorization_pending` = continue, `slow_down` = +5 s on the interval, and a poll failure with NO parseable AAD error body = a transport hiccup, keep polling. One operator interaction per run. reference.md §2026-09-07. **A token lives one resource**: the Azure CLI public client gets you Power BI REST (Gen1 `model.json`, `/transactions`), but the SAME client's SharePoint-scoped token is refused by SharePoint REST (`401 {"error":"invalid_request"}`, also via refresh-token exchange) — read tenant files through Microsoft Graph instead. Pre-resolve BOTH the login host and the target host before issuing a code (a resolver outage mid-poll ended one flow in `invalid_grant`), log `error_description`, name the account the operator must pick, and cap a session at two or three codes. reference.md §2026-09-08. |
| Local PBIP is older than the published model | Diff `getDefinition` (TMDL + PBIR) against the local folder FIRST; if it moved, rebuild: those definitions + the REST report `Export` PBIX's `DataModel` part as `.pbi\cache.abf` + a `byPath` `definition.pbir` + the previous `.platform`/`localSettings.json` files. Desktop opened it with every partition Ready (service data), applied the edits; save once from Desktop. reference.md §2026-10-20. |
| A model you published comes back with your change reverted (someone republished an older copy) | Classify LIVE against OURS and against BASE: live = base but not ours means our change was lost; live differs from base means theirs. Rebuild from live definitions + Export PBIX data and re-apply only our deltas as anchored edits, so their changes ship with ours. The Export API can sit at 0 bytes for ~10 min: background it. reference.md §2026-10-23 round 5. |
| Publish from Desktop with no operator | Drive it through UI Automation: ribbon BUTTON "Publish", "Do you want to save your changes?" Save, LISTITEM of the workspace + "Select", "Replace this dataset?" Replace, "Success!" Got it (separate top-level windows with full UIA trees). Replace leaves the items in their folder, role members included. Check after with impersonated queries (a "no role" answer for a nested-group member right after the publish can be transient: recheck minutes later), then Update app over CDP, which has no API (round 13). A tenant policy can block creating Pipelines ("Item creation blocked"): test one before designing a scheduled load around it; a Power Automate flow (Office Script returning the sheet as JSON, SQL Server connector, Power BI query and refresh actions) stands in. reference.md §2026-10-27 rounds 9 and 10, §2026-10-28 round 13. |
| A scheduled flow must read a published model at volume (hundreds of DAX questions a run) into SQL | Generate the questions in SQL (a procedure returning entity, key and DAX), loop them with concurrency set explicitly to 1, and stage `string(firstTableRows)` through a procedure that checks a row count every answer carries (`"__n", COUNTROWS(t)` over a VAR: the 15 MB cap cuts silently). Run the rules as separate procedure calls, each timed first: the SQL Server connector ends a call after 110 s, Power BI takes 100 calls a minute per connection. Rehearse the exact path from a machine with the answers as RAW JSON text and compare the built sets. A stopped flow refuses a manual run (`WorkflowTriggerIsNotEnabled`); `@{...}` turns NULL into empty text. reference.md §2026-10-28 round 12. |
| Publish while the Windows session is locked (Desktop's publish dialogs hang) | Fabric updateDefinition: model = definition.pbism + every definition/**.tmdl; report = definition/** + StaticResources/** + the PUBLISHED report's own definition.pbir (byConnection) from getDefinition; then refresh. RLS role members are kept: verify with impersonated executeQueries of role members who are not workspace members, before and after. Keep the getDefinition output as the rollback. reference.md §2026-10-30 round 16. |
