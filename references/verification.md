# Verification

Gates, fingerprints, parity proofs, engine operations, captured-query replay and memory measurement. Rows moved verbatim from the v1 SKILL.md quick reference in v2.0.0; `§` references point to [reference.md](../reference.md). Where a row disagrees with the core, the row wins.

The core's validation checklist (EVALUATE each new measure, refresh new tables, INFO functions for metadata) is the minimum. For changes to existing models these rows are the acceptance bar.

| Situation | Rule |
|---|---|
| Verifying a trim | Numeric fingerprint (values, ordered, volatility-flagged) + engine recalc + partitions all `State=1` + captured-query perf replay. |
| Timed-out `Invoke-ASCmd` | The server keeps executing. Sweep orphans: `<Cancel><SPID>n</SPID></Cancel>`. Never run suites while the user works in Desktop. |
| Recalc says "no errors" but partitions not Ready | The recalc result lies; read TMSCHEMA_PARTITIONS states: **5 = EvaluationError (root cause)**, 7 = its cascaded victims, 3 = NoData awaiting refresh. Fix the State-5 object's formula. |
| Measuring a published model's memory footprint / finding the expensive columns | REST `executeQueries` rejects EVERY `INFO.*` function on some datasets (even `INFO.TABLES()`; detail is just "Failed to execute the DAX query"), so storage DMVs need XMLA - and XMLA refuses an Azure-PowerShell token ("Authentication failed for all authenticators"). Working route: a recent ADOMD (DAX Studio's build, assembly 19.84, has `AccessToken`; an old SSMS one does not) under **PowerShell 5.1** (pwsh7 = `CallContext` type-load error), **preload the whole DLL folder** (a lazy AssemblyResolve handler = StackOverflow), connect with NO credentials for an interactive prompt in a REAL window, and read rows in a manual loop (`DataTable.Load` throws "Failed to enable constraints"). Size = SUM(USED_SIZE) over segments + SUM(DICTIONARY_SIZE) over columns; strip `\s*\(\d+\)$` from COLUMN_ID before diffing two models. reference.md §2026-09-04. |
| Proving a REBOUND report shows the same numbers on a rebuilt model | Rebuild each visual's DAX from `visual.query.queryState` (Column → grouping, Measure/Aggregation → value; `TOPN(300, SUMMARIZECOLUMNS(...), every grouping col, ASC)`), de-duplicate the text (805 visuals → 116 queries), run the SAME text on both models via `executeQueries`, split keys/values by name shape (`T[C]` vs `[v1]`). Traps: a measure-less `SUMMARIZECOLUMNS` IGNORES its filter argument (446,432 towns = all history vs 310,250 with a row-count value — add `"n", COUNTROWS(fact)`); field-parameter tables reject one grouped column (compare with `SELECTCOLUMNS` over the table); `Aggregation.Function` 5 = ROW count (`COUNTA`), 2 = `DISTINCTCOUNTNOBLANK`; export the inventory BEFORE any `-OnlyIds` filter; a PowerShell helper named `Diff` silently runs `Compare-Object` (aliases beat functions); `pwsh -File` binds `[string[]]` as one string. 20-column detail tables with a selector table in the grouping cannot run over REST even for one day — cover their columns with per-month aggregates + one document's line detail. reference.md §2026-09-04 round 2. |
| Inventory of what a report can no longer show after source columns are lost (placeholders in the model) | A static DAX closure flags every measure with ONE branch on a placeholder: 202 of 805 visuals here, while the real loss was 2 options of one selector slicer, 4 of 18 KPIs, 3 table rows and 5 filter cards. Evaluate each affected measure the report uses as a grid over the selector tables it SWITCHes on (`SUMMARIZECOLUMNS(Sel[Option], Sub[Option], KPI[Name], <month filter>, "v", [m])`) on the rebuilt AND the original model; a cell is missing when the original is non-zero and the rebuild blank or 0. Per KPI judge its value measure only (one-KPI display flags return rows for every KPI); read result rows by position (two `[Name]` columns collide); diff the published report against the local PBIR before trusting a local scan. To prune, first look for a switch the report already has (a hidden report filter feeding a visibility measure used as a visual filter): one literal flip removed two options from 10 slicers. reference.md §2026-11-07 round 18, §2026-11-08 round 19. |
| Diffing detail sets pulled through `executeQueries` | It TRUNCATES large results silently (846,945 rows → 82,168 on one model, 82,295 on the other; 88,266 phantom diffs). `COUNTROWS` server-side first; diff server-side aggregates. A model's "refreshed today" may mean ONE partition (`Orders_1`) - read the refresh record's objects before comparing months. reference.md §2026-09-09. |
| Before writing "parity proven" | Commission an adversarial second-model review with the read-only ids and the REST recipe: in ~40 min it overturned "the rebuild is right wherever it differs", "these differences are refresh lag" and "same window on both sides". Its winning methods: bucket-signature diffs keyed by two dates, per-first-character set fingerprints (count, Σlength, Σchar codes) instead of distinct-count equality, and reading the ORIGINAL partition generator instead of assuming its grain. Also only a reviewer noticed: dictionaries keep FIRST-SEEN casing (`ANYTOWN` vs `Anytown` in slicers) and a per-quarter archive projection lags a month-precise rule by a quarter. reference.md §2026-09-04 round 2. |
| Parity gate over FX-converted measures | Every `SUMX(… / IFERROR(LOOKUPVALUE(rate, cur[Currency], SELECTEDVALUE(cur[Currency], BLANK()), date), 0))` measure is **NaN** with no single currency in filter context (LOOKUPVALUE no-match returns BLANK; IFERROR never fires) — a NaN-vs-NaN comparison PASSES vacuously (20 of 111 measures, 1,027 of 6,132 rows here). Compare non-finite values as strings, re-run those measures with one currency pinned via `TREATAS`, require a non-finite count of 0, and report verified-vs-undefined coverage. |
| Enumerating a report's binding surfaces / trusting a gate that PASSed | Page `pageBinding` (drillthrough parameters) is a binding surface a visuals+`filterConfig` walker misses — 60 parameter fields on 6 visible pages, `refs=645` → `705`. General defence: print a SCALE COUNT on every PASS line (pages/refs, visuals/selectors, fields scanned, files swept, files compared, strings scanned) so a forgotten surface is a counter that never moves and a vacuous pass is visible — blinding the `pageBinding` walk dropped `fields_scanned` 2,896 → 2,776, exactly 60 x (Entity+Property). reference.md §2026-09-07. |
| Gating visuals over REST `executeQueries` | Three ways a FAILURE scores as a PASS: (1) a 200 that is not an executeQueries payload — all five reachable variants passed a naive check and a `rows:"oops"` body even scored **rows=1** (`@($null).Count` is 1); assert a `tables` node whose first table's `rows` is an ARRAY (empty array = a legitimate empty result), and note `results[0].tables[0]` on a 200-carrying-`error` throws `Cannot index into a null array` and aborts the whole run. (2) a 429 loop whose `continue` skips the error assignment — exhausted retries leave `rows=0, error=null`; guard after the loop. (3) a transport failure recorded as a query defect: NO HTTP status = transport (`HttpRequestException: No such host is known. (api.powerbi.com:443)` killed 1 of 55 queries and the gate), retry 3x at 5/15/30 s, and transient 5xx with it; anything WITH a status is an answer — record it (429 keeps its own budget). Also `$x \| ConvertTo-Json` emits nothing for 0 elements and a bare object for 1 — use `-InputObject @($x)`. reference.md §2026-09-07. |
| Reviewing a BUILT artefact with no version control | Classify every target file against its SOURCE — byte-identical / modified / added / deleted — reconcile the classes to the total (236 files = 199 + 33 + 1 + 3) and print SOURCE→TARGET diffs ONLY for the modified class; the identical class then needs no reading at all. Per Rule 7 the gate must recompute that classification from the source bytes and transcribe its expected sets from the SPEC, never read the builder's own ledger. Traps: a test suite that overwrites the real evidence ledger with its temp-target one (put the target path IN the ledger, run the real build LAST), and `rmtree(ignore_errors=True)` half-wiping a target locked by an open Desktop while the summary still reads correct (drop `ignore_errors`, assert both trees are gone before writing, keep a pristine pre-build backup). reference.md §2026-09-07. |
| Emulating a measure fix with query-scoped `DEFINE MEASURE` | Other MODEL measures keep the model definition of an overridden measure: redefine the whole chain up to every value you read. `executeQueries` returns only the first `EVALUATE`. reference.md §2026-10-20. |
