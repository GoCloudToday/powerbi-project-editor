# Desktop and harness

Headless Desktop cycles, hidden dialogs, locked sessions, Desktop's local cache, PowerShell traps and byte-identical JSON. Rows moved verbatim from the v1 SKILL.md quick reference in v2.0.0; `§` references point to [reference.md](../reference.md). Where a row disagrees with the core, the row wins.

With the CLI installed, `powerbi-report-author preview --host desktop` (status, reload, reload-with-model, screenshot) replaces a restart cycle for report reloads. Check first that no other Desktop window is open and nobody is working in Desktop. `--reload-with-model` loads TMDL without processing it: follow the core's processing table and Iron Rule 1.

| Situation | Rule |
|---|---|
| No operator available | Desktop cycles work headlessly: `Start-Process <pbip>` → poll msmdsrv port → verify → `Stop-Process -Force` (kill is cache-safe). Cloud-sourced refresh is NOT headless (dataflow auth fails out-of-band) — batch M edits for one user refresh; LOCAL-file sources DO refresh headlessly via a TMSL `refresh` on Desktop's port with `fastCombine` set (24 CSV partitions in 25 s, reference.md §2026-09-14); a SQL-sourced composite refreshes headlessly too, but "refresh returned" is not "refresh succeeded": the XMLA reply can be all `<Error>` nodes while the call returns normally — after EVERY headless refresh assert the data (COUNTROWS a small import table) or partition states, never the elapsed time (reference.md §2026-09-27). |
| Desktop won't load an edit (invisible dialog) | Validate offline: TOM `TmdlSerializer` parse + throwaway deploy to a live engine (see reference.md §2026-07-17). Desktop opens cache.abf's OLD schema first — poll for the NEW table count before judging. |
| Headless Desktop screenshots all carry a "Working on it" dialog | A TMSL refresh over the engine port followed by the ribbon Refresh left it up for minutes with the engine idle; use the ribbon Refresh alone and gate the shots on no other visible Desktop window plus every partition ready, twice. UIA names of report content use U+00A0 between words: compare names after replacing it. A black window with "There's a problem with WebView2" (UIA tree down to the shell) means the canvas died under the session: restart Desktop. reference.md §2026-10-23 rounds 6 and 8. |
| Headless Desktop open of a composite model stays "Untitled", catalogs empty | It is waiting on "Potential security risk ... multiple data sources" (every open when an import table, even a source-less `#table`, sits next to DirectQuery): UIA window by that title, `BUTTON` "OK", `Invoke()`. A new database first shows its SQL credential dialog: one sign-in by the owner. reference.md §2026-10-23 round 4. |
| Auditing PBIR JSON with a PowerShell walker | On `ConvertFrom-Json -AsHashtable` output, `$node.Values` (also `.Keys`/`.Count`) resolves to a JSON KEY of that name when present — a pivotTable's queryState HAS a "Values" key, so the walker skips the Rows role and every matrix reports false unbound fields (measures fine = the signature). Enumerate with `$node.GetEnumerator()`; methods are never shadowed. reference.md §2026-08-27 round 2. |
| Verifying Desktop work while the machine is LOCKED | `run.it`, `wnd.find`, and `Elm[...].Find/Invoke` all work without the input desktop — click Refresh by element, then watch completion via OleDb DMV polling (TMSCHEMA_PARTITIONS states) and read results with DAX; only screenshots/keyboard/save need the unlocked session. **But a NEW Desktop instance launched into a locked session never attaches the model**: window stays "Working on it", `DBSCHEMA_CATALOGS` empty, Desktop and msmdsrv idle (CPU +0.2 s / 10 s) — 4 of 4 attempts over 20 min each, incl. from a local non-synced copy, while 3 of 3 launches before the lock loaded in ~55 s. Check `Get-Process LogonUI` before launching; if locked, use an engine that is already open or queue the run on unlock (poll LogonUI absent). reference.md §2026-09-08 round 2.  **LogonUI alone is not proof**: on another run it was present all session while Desktop opened, attached 16 tables in 11 s and refreshed normally - judge by the window title ("Untitled - Power BI Desktop" while loading, the project name once attached) and the DMV table count. reference.md 2026-09-20. |
| Cloning a model onto its OWN `cache.abf` | Copy the model folder MINUS `.pbi\localSettings.json` (it pins the published datasetId), fresh `logicalId`s, partition M byte-identical — every existing table's data survives the first open (30 of 31 partitions `State 1`, only the added table `State 3`); one refresh finishes it. Poll readiness by table NAMES (must-have / must-not-have), never by count: Desktop restores the OLD schema first and both caches can hold the same table count. |
| Writing PBIR/model JSON that must stay byte-identical to Desktop's | Desktop serialises doubles with .NET Framework `"R"` (`G15`, falling back to `G17` when 15 digits don't round-trip) — `json.dumps` shortest-repr differs (`643.3333333333334` vs `643.33333333333337`; 18,816 vs 18,818 bytes on one file). It applies to EVERY JSON in the project, not just `diagramLayout.json`. Custom float formatter + a whole-tree round-trip sweep (779/779 files) — without it you cannot claim "N files byte-identical" and every unchanged visual has to be re-read by eye. Residual: exponent doubles still differ (`1e-07` vs `1E-07`). reference.md §2026-09-07. |
| Harness scripts in Windows PowerShell 5.1 | `@()`-wrap rowsets — `.Count` of one unrolled `PSCustomObject` is `$null` (a readiness loop never saw the single catalog). BOM-less UTF-8 scripts are read as ANSI, so non-ASCII literals break. Prefer PowerShell 7. |
| Desktop visuals show "This might be caused by a capacity or license issue" | It is the generic DirectQuery source-connection error card, not licensing — the refresh XML or a DMV shows the real error. The card is STICKY: it survives TMSL refreshes and page switches; only the ribbon Refresh (UIA `Invoke()` on the button) or a reopen re-renders the visuals. reference.md §2026-09-27. |
| Need a PBIP model's rows but Desktop cannot run (low RAM) or no sign-in is at hand | Wrap `.pbi\cache.abf` as the single `DataModel` entry of a stored zip (in %TEMP%, not the synced project) and open it with pbixray: a 577k-row fact decodes in 16 s. The rows are as of the last LOCAL refresh, so print the max dates with every figure. M-semantics questions settle in seconds with Excel's mashup provider over COM. reference.md §2026-10-15 round 3. |
| Desktop is already running when a headless cycle starts | It may hold ANOTHER project: DON'T start a second instance next to it. All Desktop windows share one WebView2 (the report view); two capture cycles (open, refresh, force-kill) next to an operator's Desktop left that window with "There's a problem with WebView2" and a black canvas, its WebView2 gone the same second the cycle's Desktop was killed. Ask for it to be closed, or hand the open to the operator; make helpers refuse while any Desktop runs. If you must share the machine anyway: resolve instances by `Win32_Process.CommandLine` (or a before/after pid diff, stored with the process start time against pid reuse) and engines by `ParentProcessId`, never "first PBIDesktop / first msmdsrv", never kill the other; scope UI-automation dialog finders to the report window's process id. Audit the CLOSE step too: an older `Get-Process PBIDesktop | Stop-Process -Force` (and every msmdsrv) kills the other session's Desktop; close by command line and parent pid, and refuse while another Desktop runs. reference.md §2026-10-23 rounds 5, 7 and 8. |
| Two runs of a PowerShell generator differ in every JSON file | `@{}` key order is randomized per process (.NET string hashing): the byte diff is noise, the content is equal. Compare order-insensitively, and distrust a comparer that says EVERYTHING changed (`ConvertTo-Json -Depth` above 100 throws, and a try/catch fallback to raw text then reports every file). Generate with `[ordered]@{}` where stable files matter. reference.md §2026-10-23 round 7. |
